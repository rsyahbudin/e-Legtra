# 📦 Panduan Deployment e-Legtra ke Server

Dokumen ini menjelaskan langkah-langkah deployment aplikasi **e-Legtra** (Laravel 12 + Livewire + Oracle DB) ke server kantor di subdirectory `http://10.11.12.13/e-legtra`.

---

## 1. Prasyarat Server

Pastikan server sudah memiliki komponen berikut:

| Komponen          | Versi Minimum | Keterangan                                      |
|-------------------|---------------|--------------------------------------------------|
| **PHP**           | 8.2+          | Disarankan PHP 8.4                               |
| **Composer**      | 2.x           | Dependency manager PHP                           |
| **Node.js**       | 18+           | Untuk build frontend (Vite + Tailwind)           |
| **npm**           | 9+            | Terinstal bersama Node.js                        |
| **Oracle Client** | 19c+          | Oracle Instant Client (untuk `oci8` extension)   |
| **Web Server**    | -             | Nginx (disarankan) atau Apache                   |
| **Supervisor**    | -             | Untuk menjalankan queue worker & scheduler        |

### PHP Extensions yang Diperlukan

```
php-cli
php-fpm
php-mbstring
php-xml
php-curl
php-zip
php-bcmath
php-json
php-tokenizer
php-fileinfo
php-oci8          # WAJIB untuk koneksi Oracle
```

> [!IMPORTANT]
> Extension `php-oci8` adalah **wajib**. Pastikan Oracle Instant Client sudah terinstall dan `oci8.so` sudah di-load di `php.ini`.

Untuk memeriksa apakah `oci8` sudah aktif:
```bash
php -m | grep oci8
```

## 2. Persiapan Source Code

### 2.1 Clone Repository

```bash
cd /var/www
git clone <URL_REPOSITORY> e-legtra
cd e-legtra
```

### 2.2 Set Permission

```bash
# Pastikan web server user (www-data / nginx) punya akses
sudo chown -R www-data:www-data /var/www/e-legtra
sudo chmod -R 775 storage bootstrap/cache
```

## 3. Install Dependencies

### 3.1 PHP Dependencies (Composer)

```bash
composer install --optimize-autoloader --no-dev
```

> [!NOTE]
> Flag `--no-dev` akan mengabaikan package development seperti `pestphp/pest`, `laravel/pint`, dll yang tidak diperlukan di production.

### 3.2 Frontend Dependencies (npm)

```bash
npm install
npm run build
```

Setelah `npm run build`, folder `public/build/` akan berisi asset CSS dan JS yang sudah di-compile. **Folder ini yang digunakan oleh production.**

## 4. Konfigurasi Environment

### 4.1 Buat File `.env`

```bash
cp .env.example .env
php artisan key:generate
```

### 4.2 Edit `.env` untuk Production

```dotenv
APP_NAME="e-Legtra"
APP_ENV=production
APP_KEY=<auto-generated>
APP_DEBUG=false
APP_URL=http://10.11.12.13/e-legtra
ASSET_URL=/e-legtra

# ─── Oracle Database ────────────────────────────────────
DB_CONNECTION=oracle
DB_HOST=<IP_ORACLE_SERVER>
DB_PORT=1521
DB_SERVICE_NAME=<SERVICE_NAME_ORACLE>
DB_USERNAME=<ORACLE_USERNAME>
DB_PASSWORD=<ORACLE_PASSWORD>

# ─── Session, Cache, Queue (gunakan oracle_internal) ────
SESSION_DRIVER=database
SESSION_CONNECTION=oracle_internal
SESSION_LIFETIME=60
SESSION_ENCRYPT=false
SESSION_PATH=/e-legtra
SESSION_DOMAIN=
SESSION_SAME_SITE=lax
SESSION_SECURE_COOKIE=false

QUEUE_CONNECTION=database
DB_QUEUE_CONNECTION=oracle_internal

CACHE_STORE=database
DB_CACHE_CONNECTION=oracle_internal

# ─── SSO ────────────────────────────────────────────────
SSO_LOGOUT_URL="https://sso.domain-kantor.com/sso"

# ─── File Storage ───────────────────────────────────────
FILESYSTEM_DISK=local
LEGAL_DOCS_ROOT="/path/ke/folder/dokumen/legal"

# ─── Mail (Office 365) ──────────────────────────────────
MAIL_MAILER=smtp
MAIL_HOST=smtp.office365.com
MAIL_PORT=587
MAIL_USERNAME=<EMAIL_PENGIRIM>
MAIL_PASSWORD=<PASSWORD_EMAIL>
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS="<EMAIL_PENGIRIM>"
MAIL_FROM_NAME="${APP_NAME}"

# ─── Logging ────────────────────────────────────────────
LOG_CHANNEL=stack
LOG_STACK=single
LOG_LEVEL=warning
```

> [!CAUTION]
> - **`APP_DEBUG` WAJIB `false`** di production untuk menghindari kebocoran informasi sensitif.
> - **`APP_ENV` WAJIB `production`**.
> - **`ASSET_URL=/e-legtra`** — Wajib diisi agar CSS/JS asset ter-resolve dengan benar di subdirectory.
> - **`SESSION_PATH=/e-legtra`** — Wajib agar session cookie terisolasi ke path `/e-legtra`.
> - Pastikan `LEGAL_DOCS_ROOT` menunjuk ke folder yang benar dan web server memiliki akses read/write.

## 7. Konfigurasi Web Server (Subdirectory `/e-legtra`)

Karena aplikasi diakses melalui subdirectory (`http://10.11.12.13/e-legtra`), konfigurasi web server berbeda dari deployment biasa.

### Nginx (Disarankan)

Tambahkan blok `location` berikut ke konfigurasi Nginx server yang sudah ada di `10.11.12.13`:

```nginx
server {
    listen 80;
    server_name 10.11.12.13;

    # ... konfigurasi lain yang sudah ada ...

    # ── e-Legtra (subdirectory) ──────────────────────────
    location /e-legtra {
        alias /var/www/e-legtra/public;
        index index.php;

        # Ukuran upload max (sesuaikan kebutuhan)
        client_max_body_size 50M;

        try_files $uri $uri/ @elegtra;

        location ~ \.php$ {
            fastcgi_pass unix:/var/run/php/php8.4-fpm.sock;
            fastcgi_param SCRIPT_FILENAME $request_filename;
            include fastcgi_params;
        }

        location ~ /\.(?!well-known).* {
            deny all;
        }
    }

    location @elegtra {
        rewrite /e-legtra/(.*)$ /e-legtra/index.php?/$1 last;
    }
}
```

```bash
sudo nginx -t
sudo systemctl reload nginx
```

> [!WARNING]
> Perhatikan penggunaan `alias` (bukan `root`) untuk subdirectory. Ini memastikan Nginx mencari file di path yang benar.

### Apache (Alternatif)

Pastikan `mod_rewrite` dan `mod_alias` aktif. Tambahkan blok berikut ke konfigurasi Apache:

```apache
Alias /e-legtra /var/www/e-legtra/public

<Directory /var/www/e-legtra/public>
    AllowOverride All
    Require all granted

    # Penting: agar rewrite base benar
    <IfModule mod_rewrite.c>
        RewriteEngine On
        RewriteBase /e-legtra/
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteCond %{REQUEST_FILENAME} !-d
        RewriteRule . /e-legtra/index.php [L]
    </IfModule>
</Directory>
```

> [!NOTE]
> Jika menggunakan Apache, pastikan file `public/.htaccess` yang bawaan Laravel **diganti** dengan `RewriteBase /e-legtra/` agar routing berfungsi.

## 8. Supervisor (Queue Worker & Scheduler)

### 8.1 Queue Worker

Aplikasi ini menggunakan queue untuk mengirim email dan proses lainnya. Buat file Supervisor di `/etc/supervisor/conf.d/e-legtra-worker.conf`:

```ini
[program:e-legtra-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/e-legtra/artisan queue:work database --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/var/www/e-legtra/storage/logs/worker.log
stopwaitsecs=3600
```

### 8.2 Scheduler (Cron Job)

Laravel Scheduler digunakan untuk:
- **Update status kontrak expired** → setiap hari pukul 00:00
- **Kirim email reminder kontrak** → setiap hari sesuai jam yang dikonfigurasi di Settings

Tambahkan cron job berikut:

```bash
sudo crontab -u www-data -e
```

Tambahkan baris:
```cron
* * * * * cd /var/www/e-legtra && php artisan schedule:run >> /dev/null 2>&1
```

### 8.3 Jalankan Supervisor

```bash
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start e-legtra-worker:*
```

## 10. Verifikasi Deployment

Setelah semua langkah di atas selesai, lakukan pengecekan:

```bash
# 1. Cek koneksi database
php artisan tinker --execute="DB::connection()->getPdo(); echo 'DB OK';"

# 2. Cek health endpoint
curl http://10.11.12.13/e-legtra/up

# 3. Cek queue worker
sudo supervisorctl status e-legtra-worker:*

# 4. Cek scheduler (tunggu 1 menit)
php artisan schedule:list

# 5. Cek log jika ada error
tail -f /var/www/e-legtra/storage/logs/laravel.log
```

> [!TIP]
> Buka browser dan akses `http://10.11.12.13/e-legtra`. Jika halaman login muncul dengan benar (termasuk CSS/JS), deployment berhasil.

## 11. Update / Re-deployment

Ketika ada perubahan kode baru, jalankan langkah berikut:

```bash
cd /var/www/e-legtra

# 1. Maintenance mode ON
php artisan down

# 2. Pull kode terbaru
git pull origin main

# 3. Install dependencies
composer install --optimize-autoloader --no-dev

# 4. Build frontend
npm install
npm run build

# 5. Clear & rebuild cache
php artisan optimize:clear
php artisan optimize

# 6. Restart queue worker
sudo supervisorctl restart e-legtra-worker:*

# 7. Maintenance mode OFF
php artisan up
```

## 12. Troubleshooting

### Halaman Blank / Error 500
```bash
# Cek log
tail -50 storage/logs/laravel.log

# Cek permission storage
sudo chmod -R 775 storage bootstrap/cache
sudo chown -R www-data:www-data storage bootstrap/cache
```

### Vite Manifest Error
```bash
# Pastikan build sudah dijalankan
npm run build
# Cek apakah folder public/build ada
ls -la public/build/
```

### Oracle Connection Error
```bash
# Cek oci8 extension
php -m | grep oci8

# Cek koneksi manual
php artisan tinker --execute="DB::connection('oracle')->getPdo(); echo 'OK';"

# Pastikan environment variables Oracle terset
echo $ORACLE_HOME
echo $LD_LIBRARY_PATH
```

### Queue Tidak Jalan
```bash
# Cek supervisor
sudo supervisorctl status

# Cek tabel jobs
php artisan tinker --execute="echo DB::table('JOBS')->count();"

# Restart worker
sudo supervisorctl restart e-legtra-worker:*
```

### Session / Login Error
```bash
# Pastikan tabel SESSIONS ada di Oracle
php artisan tinker --execute="DB::connection('oracle_internal')->table('SESSIONS')->count();"

# Clear session cache
php artisan config:cache
```
